Architecture atlas · seven plates

uconsole-cloud
a handheld, its LAN,
and one 5-minute POST

A three-tier stack for the ClockworkPi uConsole: a curses TUI and Flask dashboard on the device, an nginx/mDNS layer on the local network, and an optional Next.js dashboard in the cloud. These plates draw the mechanisms behind it: how the tiers stay independent, how little it polls, how a device proves who it is, and how every feature is isolated.

PLATE01

Three tiers, one crossing

The device is self-sufficient: the TUI, the dashboard and the scripts all read the same local substrate, and the LAN tier only wraps that dashboard in TLS and a name. Exactly one line leaves for the internet — a timer-driven POST that carries telemetry outward and accepts nothing back.

Three data paths, one poller

PLATE03

Linking a device without typing a password into a terminal

The device never sees the user's credentials. It asks for a short code, then polls a URL only it knows, while the actual authorisation happens in an already-signed-in browser. Both halves of the handshake are single-use and expire in ten minutes.

PLATE04

Three gates, and every route behind one

A single negative-lookahead regex routes each API call to the gate that fits it. Browsers carry a session and go through NextAuth. Devices carry no cookie, so /api/device/push enforces its own gate — token shape, payload shape, a size ceiling and a per-token rate limit, all checked before a byte reaches Redis. 

// frontend/src/middleware.ts
export const config = {
  matcher: [
    "/api/((?!auth|health|device/push|device/code$|device/poll|scripts).*)",
  ],
};
Defence in depth. /api/device/push sits outside the session matcher because a device has no cookie to present — and it earns that exemption in the handler, checking token shape, payload shape, body size and push rate on every request. Two different callers, two different proofs of identity, neither one trusting the other's.
PLATE05

Twenty-three features, each one isolated

The TUI builds its menu at first use from 23 independently imported feature modules, each exporting a HANDLERS dict. Because entries resolve through that dict instead of at import scope, a module that can't load is contained rather than fatal: it is recorded, its row steps aside, and the launcher and the other 22 features carry on.

PLATE06

Three speeds down one track

Editing and shipping share a single track; what differs is how far along it you travel. The console launcher prefers a source tree over the installed copy, so previewing a TUI change costs seconds — no build, no deploy. The packaging stations only come into play when you are actually cutting a .deb.
